## Як підключити станцію до брокера

Станція сама підключається до вашого MQTT-брокера як клієнт. Хмара Jackery для цього не потрібна.

1. Підніміть будь-який MQTT-брокер у локальній мережі (наприклад, Mosquitto) з логіном і паролем.
2. У застосунку Jackery **2.0.0+** відкрийте налаштування станції → MQTT і вкажіть адресу брокера, порт, логін, пароль і префікс топіків (типово `hb`).
3. Там же застосунок показує **токен** (8 цифр). Його треба передавати в кожному запиті до станції.

✅ Станція підключається з **client id, що дорівнює її серійному номеру**, протоколом MQTT 3.1.1, keepalive 60 с.

✅ Станція **сама нічого не публікує**: вона лише відповідає на запити. Щоб отримувати дані, їх треба регулярно запитувати (див. [Опитування](#опитування-як-отримувати-дані)).

## Топіки

`<prefix>` — префікс із налаштувань (типово `hb`), `<SN>` — серійний номер станції.

| Топік | Напрям | Що в ньому |
| --- | --- | --- |
| `<prefix>/device/<SN>/action` | ви → станція | ✅ запити й команди |
| `<prefix>/device/<SN>/status` | станція → ви | ✅ стан станції (type 2) |
| `<prefix>/device/<SN>/event` | станція → ви | ✅ стан системи (type 106), розетки й лічильники (type 101), помилки (type 123) |

Щоб слухати всі станції одразу: `<prefix>/device/+/status` і `<prefix>/device/+/event`.

## Формат повідомлення

Усі повідомлення — JSON. Запит:

```json
{
  "type": 25,
  "eventId": 0,
  "messageId": 1932,
  "ts": 1795556302,
  "token": "12345678",
  "body": null
}
```

| Поле | Тип | Опис |
| --- | --- | --- |
| `type` | число | ✅ тип повідомлення, див. [таблицю](#типи-повідомлень) |
| `eventId` | число | ✅ `0` для запитів, `3` для команд керування |
| `messageId` | число | ✅ довільне число. Станція повертає його у відповіді, за ним можна зіставити запит і відповідь |
| `ts` | число | ✅ Unix-час у секундах |
| `token` | рядок | ✅ токен із застосунку Jackery. Без правильного токена станція відповідає помилкою 401 |
| `body` | об’єкт або `null` | ✅ параметри запиту |

Відповідь станції має ті самі `type`, `eventId`, `messageId`, `ts`, а також:

| Поле | Опис |
| --- | --- |
| `deviceType` | ✅ тип пристрою. SolarVault 3 надсилає `3` (див. [довідник](#devicetype)) |
| `softver` | 📄 версія прошивки. ✅ Наша станція в цих повідомленнях її не надсилає |
| `body.cmd` | ✅ внутрішній номер набору даних: `106` у type 2, `120` у type 106, `110` у type 101 |

📄 Офіційна інтеграція також розбирає «пласкі» повідомлення без `body`, де поля лежать на верхньому рівні. Ми таких не бачили.

## Типи повідомлень

| `type` | Напрям | Топік | Що це | Статус |
| :-: | --- | --- | --- | :-: |
| `25` | запит | action | Стан станції | ✅ |
| `2` | відповідь | status | Відповідь на `25`: батарея, розетка AC, ліміти, Wi‑Fi | ✅ |
| `105` | запит | action | Стан усієї системи | ✅ |
| `106` | відповідь | event | Відповідь на `105`: мережа, режим роботи, потоки енергії | ✅ |
| `107` | від станції | event | Часткове оновлення (`soc`, `workMode`) | 📄 |
| `23` | від станції | event | Накопичена енергія (кВт·год) | 📄 |
| `1` | команда | action | Зміна налаштувань, `eventId: 3` | ✅ |
| `100` | запит | action | Список розеток або лічильників | ✅ |
| `101` | відповідь | event | Відповідь на `100` | ✅ |
| `102` | від станції | event | Оновлення одного підпристрою | 📄 |
| `103` | команда | action | Увімкнути/вимкнути розетку | 📄 |
| `123` | від станції | event | Помилка, напр. неправильний токен | ✅ |

> [!NOTE]
> Офіційна інтеграція також надсилає запит `type 2` («прочитати всі налаштування»). ✅ Наша станція на нього не відповідає. Дані з type 2 приходять лише як відповідь на `25`.

## Опитування: як отримувати дані

Станція не надсилає дані сама, тож їх треба запитувати.

| Що | Як часто | Запит |
| --- | --- | --- |
| Стан станції | кожні 5 с | `type 25`, `body: null` |
| Стан системи | кожні 5 с | `type 105`, `body: null` |
| Розетки та лічильники | раз на хвилину достатньо | `type 100`, `body: {"devType": 6}` і `{"devType": 2}` |

📄 Офіційна інтеграція опитує все раз на 5 с і вважає станцію офлайн, якщо 60 с немає жодної відповіді.

✅ Відповідь приходить менш ніж за секунду.

## Стан станції (type 2, відповідь на 25)

## Оновлення та статистика (type 107, 23)

### type 107 — часткове оновлення 📄

Станція може сама надіслати лише змінені поля, напр. `soc` і `workMode`. Застосовуйте їх поверх останнього стану. Ми такого повідомлення не бачили.

### type 23 — накопичена енергія 📄

Лічильники енергії з моменту запуску. **Значення ×0,01 = кВт·год.** Якщо в `body.deviceSn` вказано серійний номер підпристрою, це статистика розетки або лічильника. Якщо поля немає, там серійний номер самої станції або `"system"` — це статистика станції.

| Поле | Опис |
| --- | --- |
| `pvEgy`, `pv1Egy`…`pv4Egy` | Вироблено сонцем, усього та по входах |
| `batChgEgy` / `batDisChgEgy` | Заряджено / розряджено батарею |
| `inOngridEgy` / `outOngridEgy` | Вхід / вихід через мережевий порт |
| `inEpsEgy` / `outEpsEgy` | Вхід / вихід через розетку AC |
| `acOtBatEgy` | Розетка AC → батарея |
| `acOtOngridEgy` | Розетка AC → мережевий порт |
| `pvOtBatEgy` / `pvOtAcEgy` / `pvOtOngridEgy` | Сонце → батарея / розетка AC / мережевий порт |
| `ongridOtAcLoadEgy` | Мережевий порт → розетка AC |
| `ongridOtBatEgy` | Мережевий порт → батарея |
| `batOtAcEgy` / `batOtGridEgy` | Батарея → розетка AC / мережевий порт |

## Команди керування (type 1)

Топік `action`, `type: 1`, **`eventId: 3`**, у `body` завжди `"cmd": 5, "rc": 1` і одне або кілька полів, які треба змінити:

```json
{
  "type": 1,
  "eventId": 3,
  "messageId": 4821,

  "token": "12345678",
```

| Поле | Значення | Що робить | Статус |
| --- | --- | --- | :-: |
| `socDischgLimit` | 5–49 | Ліміт розряду, % | ✅ |
| `socChgLimit` | 50–100 | Ліміт заряду, % | 📄 |
| `maxOutPw` | 0–2500, крок 10 | Ліміт віддачі в мережевий порт, Вт | 📄 |
| `swEps` | 0 / 1 | Вимкнути / увімкнути розетку AC | 📄 |
| `autoStandby` | 0 / 1 / 2 | Режим автоматичного очікування | 📄 |
| `isAutoStandby` | 0 / 1 | Дозволити автоматичне очікування | 📄 |
| `reboot` | 1 | Перезавантажити станцію | 📄 |

📄 Межі лімітів станція може повідомити сама в полях `minSocChg` / `maxSocChg` і `minSocDischg` / `maxSocDischg`. Наша станція їх не надсилає.

✅ Окремої відповіді на команду ми не бачили. Як перевірити результат: нове значення з’являється в наступній відповіді type 2 (на запит 25), тобто через кілька секунд. Неправильний токен дає помилку [type 123](#помилки-type-123).

> [!CAUTION]
> Команди змінюють налаштування справжньої станції. Перевіряйте діапазони, а `reboot` надсилайте лише свідомо: станція на хвилину-дві перестане живити розетку.

## Розетки й лічильники (type 100–103)

### Список: запит type 100 → відповідь type 101 ✅

```json
{ "type": 100, "eventId": 0, "messageId": 5103, "ts": 1795556393, "token": "12345678", "body": { "devType": 6 } }
```

| `devType` у запиті | Що повертає |
| :-: | --- |
| `6` | Розумні розетки: `body.plugs` |
| `2` | Лічильники CT і збирачі даних: `body.cts`, `body.collectors` |

Відповідь без підключених пристроїв ✅:

```json
{ "type": 101, "eventId": 0, "messageId": 5103, "deviceType": 3, "body": { "cmd": 110, "devType": 6, "plugs": [] } }
```

📄 Відповідь type 101 — це **повний** список: пристрій, якого в ній немає, від’єднано. Списки можуть називатися `plugs`, `plug`, `socket`, `sockets`, `cts` або `ct`.

### Поля розетки 📄

| Поле | Опис |
| --- | --- |
| `deviceSn` (або `sn`) | Серійний номер розетки |
| `devType` | `6` |
| `name` | Назва з застосунку |
| `switchSta` / `sysSwitch` | Увімкнено (0/1) |
| `outPw` / `inPw` | Потужність, Вт |
| `totalEgy` | Енергія, ×0,01 = кВт·год |
| `commState` | Зв’язок: 1 — онлайн |
| `commMode` | 1 — локально (можна керувати через MQTT), 2 — через хмару (лише із застосунку) |

### Поля лічильника CT 📄

| Поле | Опис |
| --- | --- |
| `deviceSn` | Серійний номер |
| `devType` | `2`, `3` або `4`, див. [довідник](#devtype-підпристроїв) |
| `subType` | Модель лічильника, див. [довідник](#subtype-лічильника) |
| `tPhasePw` / `tnPhasePw` | Сумарна потужність: пряма / зворотна, Вт |
| `aPhasePw`, `bPhasePw`, `cPhasePw` | Пряма потужність по фазах, Вт |
| `anPhasePw`, `bnPhasePw`, `cnPhasePw` | Зворотна потужність по фазах, Вт |
| `tPhaseEgy` / `tnPhaseEgy` | Енергія: пряма / зворотна |
| `commState` | Зв’язок: 1 — онлайн |

📄 Деякі прошивки пишуть назви з великої літери: `TphasePw`, `AphasePw`, `TnphasePw` тощо.

### Оновлення одного пристрою: type 102 📄

Приходить на `event`. У `body` — `deviceSn` підпристрою і змінені поля (напр. `switchSta`, `outPw`) або масиви `plugs` / `cts`.

### Увімкнути / вимкнути розетку: type 103 📄

```json
{
  "type": 103, "eventId": 0, "messageId": 7310, "ts": 1795556302, "token": "12345678",
  "body": { "deviceSn": "PLUG0EXAMPLE01", "devType": 6, "sysSwitch": 1 }
}
```

Працює лише для розеток із `commMode: 1`.

## Корисні формули

**Потужність батареї** (+ заряджання, − розряджання), як у застосунку Jackery:

```
net = batInPw − batOutPw
```

**Навантаження** (що споживають прилади):

```
load = swEpsOutPw + outOngridPw
```

**Ємність** ❓ (SolarVault 3 Pro Max — 2,52 кВт·год на блок):

```
capacityWh = 2520 × (1 + batNum)
```

**Скільки протримається батарея:**

```
hours = capacityWh × (soc − socDischgLimit) / 100 / batOutPw
```

На практиці `batOutPw` варто згладжувати (напр. експоненційним середнім за хвилину). Втрати інвертора в `batOutPw` уже враховано. Якщо рахуєте від навантаження `load`, додайте до нього 5–10 % на втрати.

## Як знайти станцію в мережі

Станція нічого не оголошує в мережі, але підключається до брокера з client id, що дорівнює серійному номеру. Mosquitto записує це в лог, якщо в `mosquitto.conf` увімкнено:

```
log_dest file /opt/homebrew/var/log/mosquitto.log
connection_messages true
```

У лозі буде рядок:

```
1795544123: New client connected from 192.168.1.77:52042 as HS2C0EXAMPLE001 (p4, c1, k60, u'jackery').
```

Серійний номер і IP-адресу видно одразу. Токен однаково треба взяти із застосунку Jackery.

## Швидка перевірка з терміналу

Підставте свої дані (`mosquitto-clients` ставиться разом із Mosquitto):

```bash
HOST=192.168.1.50 USER=jackery PASS=secret SN=HS2C0EXAMPLE001 TOKEN=12345678

# Термінал 1: слухати відповіді
mosquitto_sub -h $HOST -u $USER -P $PASS -t "hb/device/$SN/#" -v

# Термінал 2: запитати стан станції та системи
mosquitto_pub -h $HOST -u $USER -P $PASS -t "hb/device/$SN/action" \
  -m "{\"type\":25,\"eventId\":0,\"messageId\":1,\"ts\":$(date +%s),\"token\":\"$TOKEN\",\"body\":null}"
mosquitto_pub -h $HOST -u $USER -P $PASS -t "hb/device/$SN/action" \
  -m "{\"type\":105,\"eventId\":0,\"messageId\":2,\"ts\":$(date +%s),\"token\":\"$TOKEN\",\"body\":null}"
```

## Відомі невідомі

Що ми поки не знаємо. Якщо знаєте — [допоможіть](#як-допомогти).

- Значення полів з позначкою ❓, особливо `ability`, `batState`, `socForceChg`, `wps`, `wpc`, обмеження струму.
- Чи є окрема відповідь на команду type 1.
- Як і коли станція сама надсилає type 107 і type 23.
- Як отримати версію прошивки: поле `softver` у наших повідомленнях не приходить.
- Як поводяться додаткові батареї (`batNum > 0`) і версії з сонячними входами.
- Інші коди помилок, крім 401.
